# 앱 개발 사례 — flur:Wallpaper

pxd **LeanUX Lab**(현 Lean UX Lab)이 2013년 자체 프로젝트 **Cloudia** 개발을 마친 뒤, 연말 남은 기간에 빠르게 완성해 출시한 스마트폰 배경화면 앱 **flur:Wallpaper for iOS7**의 개발 후기다. 이름 'flur'는 Flickr와 Blur의 합성어로, 인턴이 제안했다. 앱은 Flickr에서 임의의 이미지를 가져와 Blur 효과를 입혀 iOS7 스타일의 배경화면을 제공하는 심플한 서비스로, 팀원(無異)이 자신이 만든 다른 앱 weatherspark의 배경화면을 아이콘이 생기기 전에 캡처해 아이폰 배경으로 쓴다는 커뮤니티 글을 계기로 기획됐다. 국내외 앱스토어 상위권 앱과 사내 의견을 간단히 리서치해 '심플한 배경화면 + 블러 효과' 니즈가 실재함을 확인한 뒤 개발에 착수했다.

flur 개발기는 이론적으로 지향하는 **Lean UX 프로세스**(가정→MVP 제작→피드백)와 실제 실무에서의 괴리를 솔직하게 드러낸다. '빨리, 간단하게' 출시하는 것이 목표였던 탓에 가정과 피드백을 명확히 문서화하지 않고, 팀 내부 의견만으로 MVP를 만들고 수정하는 이터레이션만 반복했다는 자기반성이 담겨 있다. weatherspark의 알고리즘을 그대로 가져와 빠르게 첫 버전을 만든 대신, 콘텐츠를 자체 제작하지 않고 외부(Flickr)에 의존하는 구조가 낳은 두 가지 근본적 약점—네트워크·로딩 의존성과 메모리 관리 부담, 그리고 결과물 품질의 불균일성(사용자가 마음에 드는 배경을 얻으려면 반복해서 넘겨봐야 하는 '카드뽑기'식 경험)—을 감수해야 했다. 첫 MVP는 좌우 플리킹으로 결과물만 보여주는 극도로 단순한 형태였고, 이후 사내 테스트 피드백을 받아 저장 기능과 잠금화면 미리보기 기능을 추가하는 식으로 다듬어갔다.

출시 과정에서는 **Apple 앱 심사**의 까다로움도 함께 드러난다. 첫 번째 리젝션은 앱 이름(iOS7 Wallpaper)에 iPhone·iPad·iOS 등 애플 상표를 직접 명시하면 안 된다는 가이드라인 위반이었고, 이름을 'flur:wallpaper for iOS7'로 수정해 재등록했다. 두 번째 리젝션은 앱 디자인(특히 잠금화면 스타일)이 iOS7의 특정 UI와 지나치게 유사해 사용자 혼동을 줄 수 있다는 사유였다. 두 차례의 리젝션으로 크리스마스 연휴 전 출시 목표는 무산되고 해를 넘겨서야 출시됐으며, 필자는 연휴 시작 하루 전 심사(In Review) 상태에 들어가 연휴 내내 진행 없이 머물렀던 경험도 에피소드로 덧붙인다. 출시 이후에는 이미지 해상도와 퍼포먼스 개선, 그리고 다채로운 색상·형태를 가진 콘텐츠(예: 어린이 미술 활동 이미지)로 결과물의 품질과 다양성을 보완하는 방향으로 후속 개발을 이어갔다.

## 핵심 내용
- **flur:Wallpaper for iOS7**: pxd LeanUX Lab이 Cloudia 이후 짧은 기간에 만든 배경화면 앱, Flickr 이미지 + Blur 효과로 iOS7 스타일 배경화면 제공
- 이름 유래: Flickr + Blur의 합성어, 인턴이 제안
- 커뮤니티 관찰(weatherspark 배경화면을 캡처해 쓰는 사용자)에서 출발한 니즈 발견 → 간단한 리서치로 검증
- 이론적 Lean UX 프로세스(가정-MVP-피드백)를 명확히 따르지 않고 팀 내부 의견 기반 이터레이션만 반복했다는 자기반성적 회고
- 외부 콘텐츠 소스(Flickr) 의존 구조의 트레이드오프: 로딩·네트워크 의존성, 메모리 관리 부담, 결과물 품질의 불균일성
- 사내 테스트 피드백으로 저장 기능, 잠금화면 미리보기 기능을 추가하며 MVP를 다듬음
- **Apple 앱 심사 리젝션 2회**: (1) 앱 이름에 애플 상표(iPhone/iOS) 직접 명시 금지 위반, (2) 디자인이 iOS7 UI와 유사해 사용자 혼동 우려
- 리젝션으로 크리스마스 연휴 전 출시 목표가 무산되고 해를 넘겨 출시
- 출시 후 이미지 해상도·퍼포먼스 개선과 콘텐츠 다양성(어린이 미술 이미지 등) 확보를 후속 과제로 제시
