# Closed API와 Augmented Browsing

2011년 pxd 팀블로그를 티스토리(Tistory)로 개설하는 과정에서, 필자 無異는 팀블로그라면 당연히 있어야 할 '작성자별 글 모아보기' 기능이 없다는 문제에 부딪혔다. 티스토리 측에 문의해도 답이 없었고, 검색해보니 같은 요청이 오래전부터 올라와 있었지만 방치된 상태였다. 마침 티스토리 API가 새로 업데이트됐지만, 게시물 정보에 작성자 필드 자체가 빠져 있어 이 API로도 원하는 기능을 만들 수 없었다. 이런 경험에서 필자는 **닫힌 API(Closed API)** 문제를 제기한다. 이름은 '오픈 API'지만 실제로는 꼭 필요한 정보를 제공하지 않는 경우가 많다는 것이다. 네이버 오픈 API의 뉴스 검색 역시 네이버 자체 뉴스 검색만큼 풍부한 정보(썸네일 등)를 내주지 않는 사례로 함께 언급되며, 국내 오픈 API가 사용자 참여로 생태계를 함께 키우겠다는 취지보다는 '유행이니 마지못해 조금만 공개'하는 소극적 태도로 운영된다는 비판으로 이어진다.

이 한계에 대한 대안으로 글은 **Augmented Browsing(증강 브라우징)** 개념을 제시한다. 오픈 API가 열리기를 기다리는 대신, 클라이언트 단에서 이미 웹에 공개된 정보를 브라우저 확장 기능(Greasemonkey, Chrome·Safari extension 등)으로 가공해 사용자에게 더 유용한 형태로 재구성하는 접근이다. 필자는 이를 Rage Against the Machine의 "Know Your Enemy" 가사 "we don't need a key, we'll break in"으로 요약한다. 서비스가 만족스럽지 않을 때 사용자를 대신해 에이전트가 정보를 가공해주는 것이 문제가 될지 자문하면서도, 이용약관(EULA)에 따라 문제가 될 수 있고 검색엔진 결과의 무단 수집은 별개 사안임을 스스로 단서로 남긴다.

필자는 이 문제의식을 실천으로 옮겨, 티스토리 팀블로그 전체 글 목록을 긁어온 뒤 상단 제목 아래 표기된 작성자 이름으로 글을 매칭하는 스크립트를 직접 만들었다. 이렇게 API가 제공하지 않는 **작성자별 글 모아보기** 기능을 클라이언트 단에서 구현해, 저자 이름이나 '작성자가 쓴 다른 글 보기' 링크를 클릭하면 해당 저자의 글만 걸러볼 수 있게 했다. 이는 플랫폼이 제공하지 않는 기능을 운영자가 스스로 만들어 보완한 초기 사례로, 이후 pxd 팀블로그가 겪은 [[블로그 검색 노출과 크롤링 정책]] 문제(네이버 블로그 검색의 opt-in 색인 정책으로 인한 검색 노출 배제)와 마찬가지로, 외부 플랫폼에 종속된 팀블로그 운영이 반복적으로 마주하는 제약과 그에 대한 자체 우회라는 흐름을 보여준다.

## 핵심 내용
- **Closed API**: 이름은 '오픈 API'지만 실제로는 꼭 필요한 필드(예: 작성자)나 자사 서비스 수준의 풍부한 정보를 제공하지 않는 API
- 티스토리 게시물 API: 작성자 정보 필드 부재 → 팀블로그의 저자별 모아보기 기능 구현 불가
- 네이버 오픈 API 사례: 뉴스 검색 API가 네이버 자체 뉴스 검색만큼의 정보(썸네일 등)를 제공하지 않음
- **Augmented Browsing**: 브라우저 확장(Greasemonkey, Chrome·Safari extension)으로 웹에 공개된 정보를 클라이언트 단에서 가공해 사용자에게 유용한 형태로 재구성하는 접근
- "we don't need a key, we'll break in" — API가 막혀 있어도 이미 공개된 정보는 클라이언트 단에서 가공해 쓸 수 있다는 문제의식(RATM 가사 인용)
- EULA 위반 소지·검색결과 무단 수집 문제는 별개로 남겨둔 단서
- pxd 실천 사례: 팀블로그 전체 글 목록을 스크래핑해 작성자명으로 매칭하는 스크립트로, 티스토리에 없는 저자별 모아보기 기능을 클라이언트 단에서 직접 구현
