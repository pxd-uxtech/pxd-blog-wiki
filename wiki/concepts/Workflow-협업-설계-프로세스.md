# Workflow 협업 설계 프로세스

2010년 pxd 블로그에 소개된 이 방법론은 하나의 모바일 앱 Workflow(화면 흐름 기획서)를 여러 명의 디자이너가 나눠 그릴 때 겪는 "손발이 맞을 때까지 걸리는 시간"의 문제를 해결하기 위해 세 명의 UI 디자이너(필명 Goodwill·금룡·UXdragon)가 여러 번의 시행착오 끝에 정리한 3일짜리 협업 절차다. 여러 사람이 하나의 컨셉을 일관되게 표현하는 기획서를 만들 때 초반부터 업무를 효율적으로 나누려 하면 오히려 결과물의 통일성이 깨지기 쉽다는 문제의식에서 출발해, "먼저 다같이 하나의 머리를 갖추고, 그다음 하나의 손을 갖춘 뒤에, 마지막으로 각자 그린다"는 순서로 협업 리듬을 설계한다.

**Day1**은 모든 팀원이 같은 목표를 머릿속에 그리는 단계다. 기존 자료 리서치(1시간) → 각자 포스트잇에 상상하는 앱을 대충 그려보기(3시간) → 서로 의견을 부딪혀 가장 좋아 보이는 시안 도출(1시간) → Workflow 기획서 전체 목차(index)를 최대한 구체적으로 세우기(2시간) 순으로 진행한다. 완벽한 목차를 만드는 데 시간을 쏟기보다 전체 그림 속에서 자신이 잘할 것 같은 영역을 찾는 데 목적이 있으며, index 초안이 나오면 팀원들이 원하는 순서로 페이지를 나눠 우선 고속으로 채운다.

**Day2**는 팀 전체가 같은 손(작업 방식)을 갖추는 단계다. index 초안에 맞는 기존 Form(양식)을 도입해 각자 고속으로 채운 뒤(4시간), 대충 채워진 기획서를 두고 서로 논박하며 보완점을 찾고(2시간), Form 자체의 한계와 디바이스·앱 특성이 맞지 않는 부분을 함께 논의한다(1시간). 이 단계가 끝나면 모든 팀원이 Form의 활용법과 한계, 앱의 전체 컨셉을 공유하게 된다.

**Day3**는 각자 자신의 파트를 하루 종일 그리는 실행 단계다. 앞선 두 단계에서 이미 같은 머리와 손을 갖췄기 때문에 각자 작업해도 결과물이 한 사람이 그린 것처럼 통일된다. 퇴근 전에는 팀원들이 모여 서로의 파트를 교차 점검(cross-checking)하고, 최종적으로 해당 앱의 책임자가 전체 기획서를 정리하며 마무리한다. 원 글은 이 방식을 Workflow 협업에 한정해 소개하지만, 사용자조사·전략도출 같은 다른 협업 국면에도 유사한 원리를 적용해볼 수 있다는 여지를 남긴다.

## 핵심 내용
- 3일 구조: **Day1(공통 목표=머리) → Day2(공통 양식=손) → Day3(개별 실행 + 교차 점검)**
- 핵심 원칙: 업무를 초반부터 나누기보다 팀 전체가 목표와 작업 방식을 먼저 맞춘 뒤 분담해야 결과물의 통일성이 유지됨
- Day1 산출물은 완벽한 목차가 아니라 "각자 어디를 맡을지 판단할 수 있는 정도"의 index
- Day2에서 Form(양식) 자체의 한계를 미리 발견해 디바이스·앱 특성에 맞게 보완
- Day3의 마무리는 팀원 간 크로스체킹 + 책임자의 전체 정리로 완결
