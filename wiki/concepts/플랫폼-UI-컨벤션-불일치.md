# 플랫폼 UI 컨벤션 불일치

2010년경 안드로이드의 체크박스는 기존 데스크톱 OS의 관례와 정반대되는 상태 표현을 사용해 혼란을 유발했다. 맥 OS를 비롯한 PC 환경에서는 오랫동안 흐릿하게(dimmed) 표시된 체크 아이콘이 "**체크는 되어 있지만 사용자가 수정할 수 없도록 비활성화된 상태**"를 의미해왔다. 그런데 안드로이드는 똑같은 시각적 표현—체크 아이콘이 흐리게 나온 상태—을 실제로는 **아직 체크되지 않은 상태**로 사용했다. 사용자는 체크 표시가 이미 눈에 보이는데도 왜 선택이 안 되는지 이해하지 못한 채 한참을 헤매고 나서야 실제 의미를 파악하게 된다.

이 사례는 **일관성(consistency)** 원칙이 하나의 제품 안에서만 지켜져서는 충분하지 않고, 사용자가 이미 익숙해진 더 넓은 플랫폼 환경—여기서는 기존 데스크톱 OS의 관습—까지 함께 고려해야 함을 보여준다. 문제는 여기서 그치지 않는다. 단말 제조사마다 이 체크박스 아이콘을 저마다 다르게 커스터마이징해 사용하면서 혼란이 한층 가중됐고, 일부 제조사 버전은 초록색 계열 색상만으로 체크 상태를 구분하도록 만들어 **색맹·색약 사용자**가 상태를 구분하기 어려운 접근성 문제까지 동반했다.

## 핵심 내용
- 안드로이드 체크박스의 dimmed 체크 표시는 데스크톱 OS의 "체크됨+비활성화" 관례와 반대로 "체크 안 됨"을 의미해 사용자 혼란을 유발
- **일관성** 원칙은 제품 내부뿐 아니라 사용자가 함께 접하는 더 넓은 플랫폼 환경의 기존 관습까지 고려해야 함
- 단말 제조사별 체크박스 아이콘 커스터마이징이 플랫폼 전반의 혼란을 가중시킴
- 일부 제조사의 초록색 단일 색상 표현은 색맹·색약 사용자에게 추가적인 접근성 문제를 유발
