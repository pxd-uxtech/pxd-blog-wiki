# 엔터프라이즈 UX 설계 원칙

**엔터프라이즈 UX(Enterprise UX)**는 "사람들이 일할 때 사용하는 프로덕트를 디자인하는 것(The design of products for people at work)"으로 정의된다. AI·빅데이터·클라우드 같은 기술이 조직 내부로 확산되면서 기업들이 **ERP(Enterprise Resource Planning, 전사적 자원 관리)** 재구축에 나서고 있는데, 기존 업무용 서비스가 단순히 여러 기능을 나열해 제공하는 데 그쳤다면, 디지털 전환기의 업무 서비스는 사용자의 단순 반복 업무를 줄이고 중요한 의사결정·판단에 쓸 시간을 확보해주는 방향으로 재설계되어야 한다. 이를 위해서는 기존 업무 화면이 시스템·제공자 관점에서 여러 기능을 욱여넣은 결과로 빠지기 쉬운 **Complicated(복잡)와 Complexity(복합) 사이**를 헤매는 상태에서 벗어나, 사용자 업무 관점으로 기능을 재배치하는 작업이 필요하다.

프로젝트를 시작할 때는 **'기존 유저 vs. 신규 유저' 축**과 **'기존 기능 vs. 신규 기능' 축**을 교차한 매트릭스로 관찰 범위를 설정하는 것이 유용하다. 이 매트릭스를 통해 어떤 기존 기능을 자동화해 새로운 기능으로 대체할 수 있을지, 그 변화가 기존 사용자와 향후 유입될 신규 사용자 모두에게 도움이 되는지를 확인하고, 기능 개선의 우선순위와 신규 개발 범위를 판단한다. 공감·관찰 단계에서는 사용자에게 최대한 간섭을 주지 않는 방식—업무 설명을 듣고 화면을 녹화하는 관찰 조사—으로 기존 사용자가 화면에서 무엇을 보고 왜 그런 판단을 내려 특정 행동을 취하는지, 즉 **사용자의 멘탈모델**을 파악하는 것이 핵심 목표다. 이렇게 파악한 반복적 세부 업무는 업무 표준화와 자동화의 대상이 되며, 이를 통해 기존 사용자와 신규 사용자 간 **업무 퍼포먼스 갭**을 줄여 상향 평준화를 이끌어낼 수 있다.

화면을 설계할 때는 서비스·시스템 관점이 아닌 **사용자의 업무 관점으로의 전환**이 핵심이다. 구체적으로는 ① 신규 기능 도입 시 기존 사용자의 메모리 로드를 최소화해 학습 부담 없이 기능이 전달되도록 하고, ② 신규 입사자의 러닝 커브를 낮추며, ③ 신규·기존 사용자 간 업무 퍼포먼스 갭을 좁히고, ④ 업무 자동화가 진행 중인 상태(진행 상황·대기 상태)를 명확히 알려주는 네 가지를 고려해야 한다. 기존 업무 플로우를 그대로 지원하는 화면이라면 기존 워딩·UI를 유지해 메모리 로드를 낮추는 것이 유리하지만, 새로운 업무 플로우를 제공하는 경우에는 오히려 기존 화면 구성요소가 새로운 흐름을 학습하는 데 방해가 될 수 있어 새로운 워딩과 구성이 필요하다. 그밖에 기존 시스템의 정책·보안·개발 제약사항을 사전에 파악해야 프로젝트 도중 방향이 번복되는 것을 줄일 수 있고, 세션 종료·체크아웃·사용자 분류 등 새 정책 방향을 클라이언트의 프로덕트 오너에게 사용자 관점에서 제안하는 것, 그리고 MVP(Minimum Viable Product) 테스트 단계에서 모든 사용자 피드백을 다 반영하기보다 명확한 기준을 미리 세워두는 것이 실무적으로 도움이 된다.

## 핵심 내용
- **엔터프라이즈 UX**: "일할 때 사용하는 프로덕트를 디자인하는 것" — 단순 기능 나열이 아니라 사용자의 의사결정 시간을 확보하는 방향
- 관찰 설계 매트릭스: **기존/신규 유저 × 기존/신규 기능** 축으로 관찰 범위와 개선 우선순위를 설정
- 관찰 방법: 최소 간섭 원칙에 따라 업무 설명 청취 + 화면 녹화로 **사용자 멘탈모델**을 파악
- 업무 표준화·자동화로 기존 유저와 신규 유저 간 **업무 퍼포먼스 갭**을 줄여 상향 평준화
- 화면 설계 4원칙: 메모리 로드 최소화 / 신규 유저 러닝 커브 완화 / 유저 간 퍼포먼스 갭 축소 / 자동화 진행 상태의 명확한 안내
- 기존 플로우 유지 시 기존 워딩·UI 재사용, 새로운 플로우 제공 시 새로운 워딩·구성이 오히려 필요
- 실무 팁: 사전 정책·보안·개발 제약 파악, 사용자 관점의 정책 제안, MVP 피드백 반영 기준 사전 수립
