# AI 프로토타이핑과 Figma Make

**AI 프로토타이핑**은 생성형 AI로 서비스 아이디어를 빠르게 실제 화면 형태로 만들어 보는 작업이다. pxd의 UX 리서처는 **Figma Make**로 미래 서비스 컨셉을 프로토타입까지 구현해 보면서, 컨셉 정의 단계와 화면 제작 단계에서 요구되는 구체성의 수준이 근본적으로 다르다는 점을 체감했다. 처음에는 배경·컨셉·주요 사용 장면만 전달하면 알아서 화면이 나올 것이라 기대했지만, 결과물은 정보 구성이 엉성하거나 팀이 중요하게 본 내용이 빠지거나 의도와 다른 경험으로 나오는 경우가 많았다.

원인은 **컨셉과 화면 사이의 빈칸**이었다. 컨셉 단계에서는 "시스템이 어떤 정보로 무엇을 판단하고 어떤 경험을 제공하는가"만 정의해도 충분하지만, 화면에서는 사용자가 지금 어떤 상태를 확인해야 하는지, 시스템이 무엇을 대신 판단했고 어디까지 보여줄지, 판단 이유를 어떤 정보로 설명할지, 사용자가 확인만 하는지 직접 개입할 수 있어야 하는지, 상세 정보를 언제 얼마나 보여줄지를 하나씩 다시 결정해야 한다. 프롬프트도 "이 화면에서는 ○○ 기능을 보여준다" 수준이 아니라, 씬을 여러 화면으로 쪼개고 화면 최상단부터 각 섹션의 정보와 메시지까지 구체적으로 써야 원하는 결과가 나왔다.

정보를 정의한 뒤에는 **어떤 UI로 표현할지**의 문제가 남는다. 한정된 화면에서는 모든 정보를 같은 깊이로 보여줄 수 없으므로 정보의 우선순위와 위계를 정해야 하고, 같은 정보도 카드·그래프·진행 상태 중 무엇으로 표현하느냐에 따라 강조점이 달라진다. Figma Make는 목적과 정보가 달라도 비슷한 UI 패턴으로 수렴하는 경향이 있었고, 이를 풀기 위해 말로 세세히 지시하는 대신 **레퍼런스 이미지**(예: 실시간 진행 현황을 위해 배달 앱 라이더 현황 화면 캡처)를 함께 전달하는 방식이 훨씬 빠르고 정확했다.

저자는 AI 프로토타이핑을 단순한 화면 제작 도구가 아니라 **컨셉 → 프로토타입 → 검토 → 컨셉 보완**을 부담 없이 반복하는 아이디어 고도화 수단으로 볼 수 있다고 정리한다. 1편의 AI Persona가 새로운 관점과 질문을 만들어 주었다면 Figma Make는 생각을 빠르게 형태로 만들어 다시 바라보게 해 주었고, 두 경우 모두 결과를 해석하고 선택하는 것은 사람의 몫이었다는 것이 결론이다.

## 핵심 내용
- 컨셉 정의와 화면 제작은 필요한 **구체성의 수준**이 다르며, AI가 UI를 만들어 줘도 컨셉과 화면 사이의 UX 경험은 자동으로 해결되지 않는다
- **Lessons Learned 1**: 컨셉을 화면으로 옮기려면 한 번 더 '번역'이 필요하다 — 사용자가 볼 정보, 상황을 이해할 메시지, 확인·조정 가능 범위까지 정의
- **Lessons Learned 2**: AI가 임의로 판단해야 하는 '빈칸'을 줄인다 — *무엇을* 보여줄지는 텍스트로 구체적으로, *어떻게* 보여줄지는 레퍼런스 이미지로 전달하고 처음부터 구체적인 입력을 주는 편이 반복 수정보다 효율적
- **Lessons Learned 3**: 빠른 프로토타이핑을 아이디어 검토·고도화의 반복에 활용 — 핵심 가치가 드러나는지, 부족한 정보와 어색한 경험이 없는지 점검
- 정보의 우선순위·위계 결정과 UI 형태 선택은 여전히 사람의 판단이 필요한 영역이며, 레퍼런스 활용이 디자이너의 레퍼런스 참고 습관의 이유를 체감하게 했다
- 핵심 태도: AI를 많이 쓰기보다 프로젝트 단계와 목적에 맞춰 적재적소에 쓰고, 사람의 고민을 대신하지 않고 폭과 깊이를 더하는 데 활용
