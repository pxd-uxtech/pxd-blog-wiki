# AI 에이전트 장기 기억과 Hindsight

AI 코딩 에이전트는 한 세션 안에서는 맥락을 잘 붙잡지만, **세션을 넘어서는 장기 기억**과 **여러 세션·프로젝트 간 기억 공유**는 여전히 비어 있는 영역이다. 어제 정한 기술 스택 결정을 새 세션에서 다시 설명해야 하고, 30분 걸려 푼 버그의 해결 과정이 다음 비슷한 문제로 이어지지 않으며, 프로젝트를 옮길 때마다 현재 맥락부터 다시 맞춰야 한다. **Hindsight**는 이 공백을 메우려는 "에이전트를 위한 장기 기억 엔진"이다.

Hindsight는 대화 로그를 통째로 저장했다가 꺼내주는 방식이 아니라 사람의 기억 방식에 가깝게 동작한다. 대화 트랜스크립트를 **narrative fact**라는 자기완결적 사실 단위로 재구성해 저장하며, 여러 턴에 걸친 맥락이 하나의 사실 안에 압축된다. 핵심 연산은 **Retain**(대화를 구조화된 사실로 변환·저장), **Recall**(지금 필요한 맥락에 맞는 기억 검색), **Reflect**(여러 기억을 종합해 인사이트·의견 형성) 세 가지다.

Retain은 fact 추출 → 엔티티 해소("그 프로젝트", "아까 그 버그"를 하나의 개체로 통일) → 임베딩 생성 → 그래프 링크 구성(시간적·의미적·엔티티 공유 연결) 단계를 거친다. 시간을 "사건이 실제로 일어난 때"와 "그 이야기를 들은 때"의 **두 축**으로 따로 기록하는 점이 특징이다. Recall은 Semantic(벡터 유사도)·BM25(키워드)·Graph(연결 순회)·Temporal(시간 근접) 네 전략을 병렬로 돌린 뒤 **RRF(Reciprocal Rank Fusion)**로 합치고 cross-encoder로 재채점해 소수만 프롬프트에 주입한다. 그래프 순회 덕분에 직접 매칭되지 않는 간접 연결 기억까지 찾을 수 있다.

## 핵심 내용
- **세션 간 기억 공백**: 에이전트는 세션 내 맥락은 유지하지만 장기 결정·디버깅 이력·프로젝트 맥락은 세션을 넘기기 어렵다
- **Retain / Recall / Reflect**: 저장·검색·종합의 3연산. Reflect는 mental model → observation → 원본 fact 순으로 근거를 따라가며 에이전트 성향까지 반영
- **Codex 연동 실전**: 설치 스크립트가 SessionStart / UserPromptSubmit / Stop 훅과 `~/.codex/config.toml`, `hooks.json`을 자동 구성
- **설정 삽질 3가지**: ① 설정 JSON의 쉼표 누락 시 에러 없이 **조용히 기본값으로 폴백** ② macOS에서 `localhost`가 IPv6(::1)로 먼저 풀려 IPv4 바인딩 서버에 연결 실패 → `127.0.0.1` 명시 ③ `dynamicBankId` 기본값 false라 모든 기억이 하나의 은행에 몰림 → `dynamicBankId: true` + `dynamicBankGranularity: ["project"]`로 프로젝트별 분리
- **4단계 검증**: Retain 로그(fact·링크 개수) → Recall 로그(검색 건수) → 세션 트랜스크립트 JSONL에서 `hindsight_memories` 태그 grep(주입의 직접 증거) → 새 세션 행동 테스트. "설정됨"과 "실제 동작"은 다르다
- **실무 체감**: 완전 자동이 아니므로 중요한 결정은 AGENTS.md 같은 문서에 남기고 Hindsight는 암묵적 맥락 보완용으로 활용(`retainMission`으로 보존 기준 지시 가능). Recall은 쿼리당 0.1~0.3초, Retain은 10초 이상 걸릴 수 있으나 백그라운드 처리. 프로젝트 단위 격리 설계가 중요
- **범용성**: Claude Code, Cursor, LangGraph, CrewAI 등에 붙일 수 있고 MCP 서버로도 노출되어 여러 에이전트가 같은 기억 저장소를 공유할 수 있다
