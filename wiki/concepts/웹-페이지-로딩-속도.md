# 웹 페이지 로딩 속도

2011년 작성된 이 글은 **싸이월드 블로그**의 극심한 로딩 지연을 관찰 사례로 삼아, 웹 페이지 로딩 속도가 사용자 경험을 좌우하는 핵심 요인임을 지적한다. 저자(無異)는 검색 결과에서 싸이월드 로고(파비콘)만 봐도 클릭을 주저하게 될 만큼 페이지가 열리는 데 10초 이상 걸린다는 점에 주목해 개발자 도구로 원인을 확인했다. 사진이 거의 없는 텍스트 위주 페이지 하나를 여는 데 서버에 **309개의 파일**(CSS 33개·HTML 40개·JavaScript 102개·이미지 134개)을 요청하고 있었으며, 중복 요청도 많았다. 저자는 이를 여러 부서가 개별 모듈을 따로 개발해 통합되지 않은 결과로 추정했다.

이 문제의 심각성은 같은 서비스 내 비교를 통해 더 뚜렷해진다. 거의 동일한 정보량을 담은 **싸이월드 모바일 페이지**는 요청 수가 37개에 불과해 1.4초 안에 열렸다. 다른 서비스들과 비교하면 다음·네이버는 약 130개, 티스토리·이글루스는 약 80개, 워드프레스는 40개 내외의 요청으로 페이지를 구성했다. 즉 요청 수 차이가 곧 체감 로딩 속도 차이로 직결되며, 페이지가 무엇을 보여주는지(UI·기능)보다 그것이 **얼마나 빨리 도달하는가**가 더 근본적인 문제일 수 있다는 것이다.

저자는 이 관찰에서 UX에 대한 하나의 원칙을 도출한다. 예쁘게 만들고 사용을 쉽게 하고 편리한 기능을 제공하는 것도 중요한 경험이지만, **참고 기다리는 것이 가장 나쁜 경험**이라는 것이다. 실제로 저자 자신도 검색 결과에서 싸이월드 블로그 링크는 화면 UI를 볼 필요도 없이 클릭 자체를 피한다고 밝힌다. 느린 페이지는 아무리 정교하게 디자인되어도 애초에 사용자가 도달하지 못하기 때문에 그 디자인이 평가받을 기회조차 얻지 못한다는 문제의식이다.

## 핵심 내용
- 페이지 로딩 시간은 HTTP 요청 수(CSS·HTML·JS·이미지 파일 개수)에 크게 좌우된다
- 싸이월드 블로그: 309개 요청 → 10초 이상 소요, 싸이월드 모바일: 37개 요청 → 1.4초
- 여러 부서가 개별 모듈을 따로 개발해 통합되지 않으면 중복 요청·요청 수 폭증으로 이어질 수 있다
- 국내 서비스 비교(2011년 기준): 다음·네이버 ~130개, 티스토리·이글루스 ~80개, 워드프레스 ~40개
- 로딩이 느리면 사용자는 화면을 보기도 전에 클릭을 피하므로, UI·기능 이전에 도달 자체가 UX의 전제 조건이 된다
- "예쁘고 쉽고 편리한 것"보다 "**기다리게 하지 않는 것**"이 더 근본적인 사용자 경험이라는 주장
